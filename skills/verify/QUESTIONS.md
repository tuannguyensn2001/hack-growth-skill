# Questions

## The difficulty ladder (Bloom levels)

| Level | The learner must… | Example question shape |
|-------|-------------------|------------------------|
| 1. Remember | recall a fact or definition | "What does X stand for / do?" |
| 2. Understand | explain it in their own words | "Why does X exist? What problem does it solve?" |
| 3. Apply | use it on a new, concrete case | "Given this input / scenario, what happens?" |
| 4. Analyze | break a case down, find the cause | "This system shows symptom Y. What's going on?" |
| 5. Evaluate | judge trade-offs, defend a choice | "X or Z here, and why? When would you switch?" |
| 6. Create | design or extend with it | "Design a solution for this new constraint using X." |

## Adapting

- **Start** each key idea at level 2 for a novice or advanced beginner, level 3 for competent and above (per `profile.md`).
- **Correct** → next question on the same idea climbs one level. Stop climbing at level 6 or when the level exceeds what the source teaches.
- **Wrong or partial** → probe one level down to find where understanding holds. If level 1 or 2 fails, suspect a prerequisite: ask one question on the concept beneath it.
- **Ceiling**: an idea is done when you've seen a correct answer at some level and a failure at the level above, or a correct answer at the top.
- **Length**: 1–3 questions per key idea, roughly 8–15 in total. Ask the learner before going longer.

## Crafting questions

- Test **use**, not recognition: from level 3 up, every question needs a new scenario the source didn't show.
- One idea per question, so a wrong answer points at one gap.
- Open-ended by default. Multiple choice only at levels 1–2, with distractors built from common misconceptions.
- Prefer questions where a shallow understanding gives a confidently wrong answer: predict the output, find the bug, explain the counter-intuitive case.
- For software: show code, input/output, or a diagram and ask about it.
- **Retest** questions target an open `mistake` memory with a fresh scenario, never the same wording as before.
- If the learner's answer is vague, ask them to commit ("Pick one and say why") once. Then grade what they gave.
